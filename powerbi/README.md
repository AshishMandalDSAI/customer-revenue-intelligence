# Power BI Guide — NovaMart CRIP

This folder contains Power BI-ready CSV exports of the pipeline's analytical output, plus
documentation for building a Power BI report on top of them.

> **What was and wasn't done:** the CSVs in `powerbi_data/` are real exports, regenerated by
> `src/business/recommendations.py` from the actual pipeline run (see row counts below — not
> placeholders). **No `.pbix` file is included** — Power BI Desktop is a Windows/licensed
> application not available in this build's sandbox, so the report itself has not been built or
> screenshotted. This guide gives you everything needed to build it yourself in a few minutes:
> which files to import, how to relate them, and ready-to-paste DAX measures.

## 1. Files to import

| File | Rows (current run) | Grain |
|---|---|---|
| `customer_360.csv` | 7,636 | One row per customer (snapshot population — see note below) |
| `monthly_revenue.csv` | 44 | One row per month |
| `customer_segments.csv` | 7,636 | One row per customer |
| `churn_predictions.csv` | 7,636 | One row per customer |
| `clv_predictions.csv` | 7,636 | One row per customer |
| `revenue_at_risk.csv` | 7,636 | One row per customer |
| `profitability.csv` | 7,658 | One row per customer (**full order-history population** — see note below) |
| `recommendations.csv` | 7,636 | One row per customer |

**Note on the two different customer populations:** `profitability.csv` has 22 more rows than
the other customer-level files. This is intentional, not an error: `profitability.csv` is
computed from each customer's *entire* order history, while `customer_360.csv` and everything
else is scoped to the churn/CLV snapshot population (customers who existed *before* the model's
snapshot cutoff — see `docs/ml_methodology.md` §1). A handful of very recently-acquired
customers have profitability data but no churn/CLV score yet. In Power BI, relate on
`customer_id` with the join set to include both matched and unmatched rows if you want
profitability figures for these customers to still show up in totals.

## 2. Import steps

1. Power BI Desktop → **Get Data → Text/CSV** → select each file in `powerbi_data/`.
2. Power BI will auto-detect types; double-check `customer_id` imports as **Text** (not a
   number) in every table, since IDs like `C100000` should never be summed/averaged.
3. Set `month` in `monthly_revenue.csv` to **Date** type (format `YYYY-MM`).

## 3. Relationships

Build a star-ish schema around `customer_360.csv` as the main fact/dimension hybrid table:

```
customer_360 (1) ──< customer_segments      (customer_id, 1:1)
customer_360 (1) ──< churn_predictions      (customer_id, 1:1)
customer_360 (1) ──< clv_predictions        (customer_id, 1:1)
customer_360 (1) ──< revenue_at_risk        (customer_id, 1:1)
customer_360 (1) ──< recommendations        (customer_id, 1:1)
customer_360 (1) ──< profitability          (customer_id, 1:many-or-none -- see population note)
```

In practice, `customer_360.csv` already contains the churn/CLV/segment/RFM columns joined in
(check its header — it's a pre-joined convenience table), so **for most visuals you only need
`customer_360.csv` + `monthly_revenue.csv` + `profitability.csv`**. Only bring in the individual
`churn_predictions.csv` / `clv_predictions.csv` / etc. tables if you want to model them as
separate fact tables for a more traditional star schema exercise.

`monthly_revenue.csv` has no `customer_id` — it's a standalone time-series table for trend
visuals; don't try to relate it to the customer tables.

## 4. Recommended report pages

1. **Executive Dashboard** — headline KPIs (see `KPI_Definitions.md`) as cards, monthly revenue
   trend line, revenue by region/segment donut/bar.
2. **Revenue Analytics** — AOV trend, revenue by category/channel, repeat-purchase-rate trend.
3. **Customer Segmentation** — segment size/revenue/churn-rate table, RFM segment bar, cluster
   scatter (use `pca_1`/`pca_2` from `customer_segments.csv` for a 2D visual).
4. **Churn & Retention** — churn rate by segment/region, risk-category distribution, high-risk
   customer table (filterable, drill into `customer_360` fields).
5. **CLV & Revenue Risk** — CLV category distribution, revenue-at-risk by segment/region,
   scatter of `expected_clv_12m` vs `churn_probability`.
6. **Customer Profitability** — quadrant scatter (`gross_revenue` vs `estimated_profit`),
   quadrant summary table, margin trend.
7. **Marketing Recommendations** — next-best-action distribution, action-filtered customer
   table with `action_reason` visible as a tooltip/detail field.

## 5. Filters & drilldowns

Add these as report-level or page-level slicers: `region`, `acquisition_channel`,
`risk_category`, `clv_category`, `segment_name`, `profitability_quadrant`,
`recommended_action`. Enable drill-down from `region` → `customer_id` on any customer-count
visual, and from `month` (year → month) on the revenue trend line.
